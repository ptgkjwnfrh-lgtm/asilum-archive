## D.3 — the hybrid search pipeline and the taste reranker (§10)

The engine already does steps 1–5 and 7 of the brief's pipeline (deterministic handle/entity parse, scope, exact + lexical + bounded semantic candidates, constraints before results leave, reasons and confidence). Stage D adds step 6 and the labels:

| Brief | Where | Status |
| --- | --- | --- |
| Rerank by the user's permitted taste profile; preserve exact entity identity and explicit constraints | `lib/search/reranker.js rerankByTaste`: rows matched on name / brand / designer / credit / title are **pinned** in the engine's order; no row added or removed; stamps (`_meta.manual`) weigh 1.0, inferred (time-decayed `long`) 0.6, hidden tags −1.5; served ids are **exposure** (−0.35), not preference; ≤ 2 rows per brand and ≥ 2 low-affinity rows in the top 12 | shipped, tested (`tests/taste-reranker.test.js`, 4) |
| Result IDs with short match reasons and source/uncertainty labels | each row leaves with `match: { reasons: [engine reason, "taste" \| "against taste"], source, uncertainty: exact \| likely \| related \| assisted }` | shipped |
| Wiring | `GET /api/search?brain=1` only (guidance on); `SEARCH_TASTE_RERANK=0` kills it; the response says `taste: { reranked, version }` | shipped |
| Explicit stamps apart from inferred; time decay; repeated impressions = exposure | already the brain's law (lib/brain/memory.js decay by class); the reranker reads them apart | as before + read apart |

**Measured, per the evaluation skill.** The canonical honesty probes (`scripts/measure-search-honesty.mjs`): **15 / 15 before, 15 / 15 after** — unchanged, because the reranker runs only on a guided search and pins exact rows. The reranker's own invariants are measured by `npm run release:checks` (identity preserved, candidate set preserved, diversity, exploration). Precision@k / nDCG / CTR need interaction volume the product does not have; not fabricated. The 1000-bot stress harness judges the FEED, not search, and was not run.

## Recommendations that change founder intent

1. **Keep the AI check's confidence below the bar until a keyed model is evaluated on fixtures** — i.e. every badge needs a human for now. The brief allows AI-alone; this is the safer default while the model is off.
2. **Name the reviewers** (ADMIN_ACTOR per person) before the first badge is issued, so the breakdown's "passed by …" is a person, not "admin".
3. **Spotify manual-only, officially** — the registry now states it; OWNER-DECISIONS §7 asks for the word.
