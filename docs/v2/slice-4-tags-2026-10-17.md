## How the engine reads a colon now

1. DESIGNER: HOUSE first (19 Sep, `lib/search/pair.js`) — a resolved pair is
   served as before, sourced tenure and all.
2. Otherwise the tag reading over the full product pool (`tagsFor` on every
   record): pieces that carry the tag; or, when the right side misses but the
   left exists, an honest empty with the left count (`nothing here is tagged
   SUPREME: CASSETTE — 19 pieces carry SUPREME:`).
3. A one-sided pair miss stays a pair miss (`nobody: gucci`); a query nobody
   carries as a tag and nobody can read as a pair is read as words, the miss
   said first (`silver: jewelry` → the words `silver jewelry`).
4. Pins (`tagFilters`) narrow whatever the reading produced; each pin is said.

The typed `product_tags` rows (scene, material, origin; an admin's row at its
own confidence) ride `/api/related` as `typedTags`, so the listing reads the
record AND the layer; the Feed card reads the record alone. A row can add tags
behind the product; it changes the visible three only when it is certain.

## Honest gaps

- Only the record's facts and the typed layer speak. Nothing here invents a
  scene, an aesthetic or a place: the house's base (`NEW YORK: VARSITY JACKET`)
  is written at 0.7 and stays behind the product until a typed origin row
  says the piece itself is from there.
- The object noun comes from the title (the catalog's "House — garment" shape,
  or the last object noun of a free title) and falls back to the department.
  The search vocabularies are the register; `OBJECT_NOUNS` in the grammar
  adds only the nouns the search ontology leaves out for its own reasons.
- Admin REWRITE (overriding a derived tag outright) is slice 5, ASTERISK
  governance; today an admin row is one more typed row.
- STAMPS still inherit the brain's aesthetic keys as taste evidence
  (`SaveButton tags=`); the grammar's identity tags are display and query,
  not yet a second evidence channel.
